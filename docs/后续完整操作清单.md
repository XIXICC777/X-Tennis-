# 从学校建档到微信发布：后续完整操作清单

适用当前进度：用户已确认正式环境管理员页面正常、正式表权限核对正确、学校已添加。学校班级如尚未添加，从第1步继续；已做完的步骤跳过，不必每步回到聊天确认。当前仍是连接正式云环境的预览版，不代表已完成微信审核发布。

正式环境ID：`zimo-prod-d6gt9vooh5852c299`。演示环境 `cx100-d3ga3i1ljcfc054ca` 保留独立使用。正式 `DEMO_MODE=false`；初始化后已把临时 `BOOTSTRAP_OPENID` 行改回 `DEMO_MODE=false`，不再重复初始化。

## 1. 添加学校班级

在手机小程序“机构管理 → 新增学校班级”，选择已添加学校，填写实际班级名称、年级数字1—6、学年起始年份。2026—2027学年填2026。点“核对并保存”，刷新后应能在班级列表看到。

不同学校的同名班级分别建立；同一学校不同班级分别建立。学校班级是共享作业的依据。

## 2. 添加机构分组

“机构管理 → 新增机构分组”，填写实际安排，如“周一至周五晚托组”。学校班级与机构分组独立：来自不同学校的孩子可以同一机构分组，但不能按机构组混发学校共同作业。

先建立当前实际用到的班级和分组，后续按需要增加。

## 3. 完成真实信息使用前的隐私配置

在微信公众平台后台找到“用户隐私保护指引／服务内容声明”，按实际收集的信息填写：学生档案、学校班级、监护关系及联系方式、作业照片、进度、成绩和必要状态事实等，并说明目的、保存期限、处理者联系方式、更正删除和导出途径。

模板参考 `docs/隐私指引模板.md`。涉及6—12岁儿童，录入真实资料前完成监护人告知及必要授权。正式环境不灌入虚构演示档案，也不把真实学生表发到聊天里。

在微信后台核实实际使用的相册/相机等接口声明与授权要求。首版有大小和格式头校验，尚未接入生产图片内容安全审核；若实际使用需要平台审核能力，应在对外使用前完成接入和验收。遇到授权或审核提示先处理，不绕开验证。

## 4. 核对索引与存储配置

正式集合应全部拒绝客户端直接读写；云存储仅管理端读写，图片通过已鉴权云函数读取。已正确设置的保持不变。

数据库索引按本文件末尾清单设置：在正式环境“数据库 → 对应集合 → 索引管理／索引 → 添加索引”中操作，类型为普通、非唯一，字段按所列次序全部升序，每一组字段各建一个索引。索引名称按控制台要求自定，例如tasks的日期索引可命名 `idx_date_id`。如果已有相同索引则跳过，保留默认 `_id` 主键索引。等待索引构建完成。

索引清单不是数据，也不是权限规则，不要粘贴进“数据导入”或“权限设置”框。若实际控制台不支持清单里的某个组合，保留错误提示再核对，不删除原有索引来尝试。

## 5. 上传内部体验版，让其他人能进入

之前上传的是api云函数；小程序代码还需通过开发者工具右上角“上传”发送到微信后台。

1. 确认当前项目填写真实AppID，客户端config指向正式环境，管理员预览正常。
2. 如果本地修改过TS，在当前项目根目录执行 `npm run build`，看到模块检查通过；仅日常录入无需构建。
3. 点击开发者工具右上角“上传”，填写递增版本号（首次可用0.1.0）和真实版本说明，等待上传成功。
4. 登录微信公众平台，进入“版本管理”，找到刚上传的开发版本，按页面入口设置为体验版。
5. 在“成员管理 → 体验成员”添加需要试用的老师微信，后续再添加已沟通好的监护人。让他们扫描体验版二维码。具体入口和人数以当前后台为准。

上传体验版不是公开发布。未完成审核发布前，普通用户不一定能搜索或打开；体验者应先加入后台允许名单。

## 6. 老师首次登录与授权

每名老师用自己的微信打开体验版，点“修改称呼”，填写真实姓名或工作称呼，再把页面“我的账号编号”提供给管理员。

管理员在“机构管理 → 授权已登录员工”填写对方账号编号、姓名和职责，启用后保存。这里用小程序页面上的账号编号，不是OPENID、AppID或云环境ID。

| 职责 | 角色填写示例 |
|---|---|
| 普通科任老师 | `teacher` |
| 兼任主责的老师 | `teacher,lead` |
| 确实需要机构管理权限的人员 | `admin,teacher,lead` |

多个角色使用英文半角逗号。新登录默认家长视角属于正常保护机制，老师经管理员授权后刷新获得相应入口。主责权限还要在具体学生档案中指定，不能只填lead就对所有学生发布反馈。

你自己的账号已经是管理员；开始时可以由你兼任主责和三科老师，之后再按实际分工调整。不要随意给所有人员管理员权限。

## 7. 学生建档

“机构管理 → 新增学生”，逐项填写真实资料：

- 唯一学生编号，例如机构自定的ZM0001，不填身份证号码。
- 学生姓名。
- 当前学校班级：选择前面建好的选项，系统据此取学校、年级与学年。
- 机构分组。
- 一位主责老师。
- 语文、数学、英语各自负责老师，可以是同一人。
- 在读开关。

核对保存后，在顶部孩子列表找到该学生，进入“学生档案”检查班级与分工。只选择已经启用且有老师职责的员工。

学年变化时先建立新学年班级，再从“学生档案 → 编辑档案／升级转班”修改当前班级，历史作业和成绩保留原班级快照。不要通过删除学生再重建的方式升年级。

## 8. 邀请并核验家长

1. 先在微信后台添加家长为体验成员，使其能打开体验版。
2. 主责老师或管理员选择孩子，进入“学生档案 → 生成24小时一次性邀请”。把邀请单独发给已确认身份的监护人。
3. 家长用自己的微信进入，在“输入邀请并申请绑定”中填写邀请码、关系和联系电话。
4. 老师在学生档案找到待核验申请，依据机构原登记联系方式或当面方式核实监护关系，填写核验依据（不录证件号码），打开核验通过并确认。
5. 家长刷新后应只看到自己已核验绑定的孩子。申请提交成功不等于已经核验。

一个孩子多位监护人，应逐人生成新邀请、逐人申请和核验；一个家长多个孩子，应分别申请。撤销时在档案中撤销对应绑定，后续读取会拒绝；已保存的截图或导出无法远程撤回。

## 9. 每天记录到店与共同作业

先检查顶部日期。选择孩子，在“今日工作台”记录到店、离店或请假，保存后刷新确认。离店另外记录，系统不推测时间。

到“同班作业”勾选同一学校班级的孩子，可用“选择今天已到店学生”。点“新增共同作业并分发”，填写日期、学校班级、科目、一次共同内容及来源。来源明确且实际核实时才打开“已核实来源”；不明确时留待核实。

语文、数学、英语分别录入需要的任务；同科可有多份任务，不把未录入当作没有作业。混选不同学校班级会被服务器拒绝。

复制旧作业：顶部切换到旧日期，勾选目标孩子，点旧共同作业“复制后修改发布”，在表内改成新日期并核对内容。原个人进度不会复制成新日进度。

## 10. 完成、检查、订正与个人例外

选中孩子，点击对应任务的“记录进度／检查／复核”。

- 未开始或进行中，孩子写完后选“待检查”。
- 亲自检查后可选“检查通过”；有问题则进入“订正中”。
- 订正后亲自复核，再选“订正已复核”并明确打开检查／复核确认开关。
- 核实待核实来源后转入未开始，也需要明确确认。
- “需要帮助”单独开关，不替换任务状态。
- 分层作业、请假补做、免做、个人订正、约定家庭加练，用个人例外及必要备注说明。

系统按状态机拒绝跳级，“检查通过”和“订正已复核”不自动等于长期掌握。共同内容要修订时从共同作业入口修改并确认影响范围，保留每个孩子既有进度。

保存失败时保留表单并原地重试，看到成功后再离开；版本冲突时刷新核对，不强行覆盖。多名老师各自处理分配的学科，未授权操作会被拒绝。

## 11. 重点问题、周目标、交接与状态支持

在“反馈与跟进”操作：

- 重点错题：填写题目位置、知识点、错误表现、已采取帮助、当日同类题验证和复查日期。仅记录有跟进价值的问题，不必每题录入。
- 照片：先选科目再上传，首版JPEG/PNG单张不超过500KB。上传成功会填写附件编号，仍须保存整张跟进卡。避免拍到无关个人信息。
- 到期复查：打开卡片记录实际结果及说明；继续支持则给下一次日期。到期不处理会继续保留为逾期，不自动消失。
- 每周目标：填写一个具体可观察目标和当周结束日期；同周更新同一个目标。
- 具体进步：至少有两条该学生复查记录后，关联前后证据再写事实变化，不生成虚构评分。
- 遗留交接：说明未完成事项、原因、下一步、负责人和期限；处理后记录结果。
- 状态支持：内部事实、已采取帮助与家长说明参考分开。家长说明参考不会自动发布，主责老师审阅后再用于反馈；不贴标签、不诊断、不打心理分。

## 12. 考试成绩录入与家长查看

选孩子 → “成绩记录 → 录入考试成绩”，填写日期、科目、名称、类型、原始得分、满分、范围、来源、核验和备注。

无成绩不要录入，缺失不会变零分；真实零分才明确填0。不同满分保留原始值，图表百分比换算不代表难度相同。家长可以按科目、考试类型、日期范围筛选，点节点或列表查看详情。

第一版没有成绩编辑／删除按钮。录错后保留问题说明，按受控维护流程更正并留操作记录；不要通过添加一条“抵消成绩”或随意删除历史数据处理。

## 13. 日报、周反馈与家长沟通

主责老师选孩子 → “反馈与跟进 → 汇总日报草稿”或“汇总近7日周反馈”。草稿从真实任务、进步与遗留记录汇总，没有记录会明确说明，不猜测收获。

打开“编辑并确认发布”，核对并补充具体收获、必要状态说明、遗留问题、家庭配合及下周重点，确认后发布。家长看不到草稿，发布后刷新可见。

家长点“标记已阅”或“需要沟通”。主责老师在待办中记录沟通结果。当前没有即时聊天和订阅消息发送，不能把页面保存当作已主动通知家长。

重要异常：从“学生档案 → 联系已核验监护人”选择联系人拨号，执行机构已有紧急联系流程，不依赖推送。

## 14. 完成小范围真实身份验收

先使用已获授权的少量真实参与者，至少包括管理员、科任老师、主责老师和两个分别绑定不同孩子的家长账号。分别验证：

1. 老师仅能修改分配学科；主责才能发布对应反馈。
2. 家长只能看到自己已核验的孩子，不能看到草稿或内部状态详细记录。
3. 两名老师同时保存不同科，刷新后双方结果都在。
4. 同班共同作业一次分发，多次重试不重复，个人例外不影响别人，共同修订不清空个人记录。
5. 作业图片上传、读取、拒绝越权，撤销绑定后再次读取拒绝。
6. 日报发布前不可见、发布后可见；成绩缺失为空，不填0。
7. Android和iOS的图片授权、图表点按、拨号与JSON文件分享。
8. 普通家长不能直接读数据库或按云存储fileID下载对象；这些原生接口测试需在对应真实身份下进行，管理员身份本就有管理权限，不能替代家长测试。

自动化45项测试已通过，用户报告演示环境手机主要操作正常；这不等于以上正式环境检查已经全部完成。接口参数篡改的服务端测试在tests中，真实规则与设备验证应另行记录。

## 15. 导出、备份和恢复

单学生导出：员工“学生档案 → 导出该孩子的JSON记录”；家长从首页底部“导出孩子学习记录”。导出按当前权限过滤，妥善保存生成文件。

第一版没有一键全库自动备份／恢复按钮。由管理员使用云平台当前支持的数据库备份或集合导出能力，并单独备份私有存储对象及文件映射；只有files表不代表图片已备份。保存索引、权限及函数版本资料，敏感导出限制访问。

在独立恢复环境先演练，再决定生产恢复。跨环境storageId可能变化，需维护映射；不要直接拿演示备份覆盖正式库。详细步骤见 `docs/架构与数据.md`。上线前确认实际云套餐的配额、备份能力、保留期、费用和到期策略。

## 16. 完成微信平台资料及审核准备

登录微信公众平台，根据真实主体与实际服务核实：小程序名称、图标、简介、服务类目、所需主体资质、认证要求、备案状态、隐私指引及实际使用接口声明。已完成且正确的项目跳过。

你目前以个人主体注册且没有营业执照；是否能用个人主体公开发布现有完整服务仍要看实际可选类目及审核要求。免费不自动免除资质要求，不能选择与真实功能无关的类目或编造经营说明。若后台要求无法提供的资质，需要处理主体或实际上线范围，不能保证直接过审。

审核体验必须可用。按平台要求提供真实可执行的体验方式；本项目依赖微信身份与绑定，没有通用账号密码。若审核要求的测试方式当前无法满足，应先安排受控审核体验流程，不能把所有新用户授予管理员或开放数据库权限。

## 17. 提交审核、发布与后续更新

1. 确认上传到微信后台的是连接正式环境的客户端版本，不含演示身份入口，云函数DEMO_MODE为false或缺省。
2. “版本管理”找到对应开发版本，按页面入口“提交审核”，如实填写功能及所需材料。
3. 如果被驳回，保留原文，按实际原因修正资料、功能或审核体验安排；不要仅靠改成不真实文案重提。
4. 审核通过后，在后台点击“发布”，再按平台提供的二维码和分享入口让用户访问。未发布时，体验版可见不等于所有家长都能搜索到。
5. 后续改代码先在独立演示环境验证，再构建、部署必要的云函数和上传小程序版本；需要时重新审核发布。保留稳定版本与备份，不清空正式库。

日常登记在手机完成，云端正常运行时不需要电脑持续开着npm服务。电脑主要用于代码构建、部署、上传以及受控维护。
