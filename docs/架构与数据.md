# 架构、数据和权限

## 运行边界

原生 TypeScript 小程序 → `wx.cloud.callFunction('api')` → 云函数校验微信身份 → 业务服务 → 云数据库事务 / 私有文件存储。

本地演示与生产使用同一 `domain.js` 业务逻辑，但演示采用独立 Node HTTP 服务及JSON持久化适配器。只有演示服务允许预设身份切换；正式云函数忽略任何客户端身份参数，只取微信上下文的 OPENID。前端缓存只有隐私说明“已阅读”标志，不存业务数据库或角色。

每个云环境服务一个机构，不接收客户端传入的机构ID做租户切换。多机构 SaaS 与独立电脑后台不在首版范围。

## 四种职责

| 职责 | 服务端判断 |
|---|---|
| 家长 `parent` | 有该学生 `verified=true && active=true` 的监护绑定 |
| 负责老师 `teacher` | 可读所有在权限范围内的机构学生三科概览；写某科必须匹配学生 `assignments[科目]` |
| 主责职责 `lead` | 由现有老师兼任，具体以学生 `leadId` 为准；主责老师可处理该学生三科、核验绑定、汇总确认发布反馈和处理沟通 |
| 管理员 `admin` | 管理基础档案、角色及分工，处理机构业务；不能把自己最后的管理员职责取消或停用自己 |

同一员工的 `roles` 是数组，可兼任。`lead` 角色本身不授予对所有孩子发布反馈的权限，必须是具体学生主责或管理员。未授权的新登录默认只有 `parent`。角色由管理员接口修改，前端设置、HTTP参数和本地存储无法提权。停用员工每次调用立即拒绝。

内部情绪详细记录仅向管理员、该学生主责或已分配学科老师提供。其他员工可以查看机构学生三科进度，但不会获得无分工学生的内部情绪记录。家长读取、导出均不含 `emotions`、监护电话和草稿。监护电话仅由主责或管理员通过 `contacts` 读取。

## 数据表

实际表名加 `zimo_live_` 或 `zimo_demo_` 前缀。每条业务记录使用固定 `id`，云数据库 `_id` 与之相同；写入自动保存UTC ISO格式 `updatedAt`，业务日期统一按北京时间计算。

| 表 | 主要字段与用途 |
|---|---|
| users | id（命名空间+OPENID散列）、服务端openid、name、roles[]、enabled |
| schools | id、规范学校name |
| classes | schoolId、grade整数1—6、schoolYear起始年份、规范班级name |
| groups | 机构教学分组name，与学校班级独立 |
| students | number唯一编号、name、schoolId、classId、grade、schoolYear、groupId、leadId、assignments语数英、active |
| bindings | studentId、userId、relationship、phone、verified、active、verifiedBy、核验evidence |
| invites | SHA256邀请码为主键、studentId、expiresAt、used、claimedBy；随机128位代码，24小时有效、单次申请 |
| homework | classId及学校年级学年快照、date、subject、content、source、verified、revision、history[] |
| tasks | studentId、homeworkId、date、subject、原班级快照、status、help、exception、note、version、changedBy、confirmedBy/At |
| attendance | 学生+日期确定主键；status、arrivedAt、leftAt、by |
| mistakes | studentId、date、subject、location、可选fileId、knowledge、symptom、support、result、reviewDate、ownerId、closed、lastResult |
| reviews | mistakeId、studentId、date、result、note、by；每次后续复查为独立记录 |
| scores | studentId、date、subject、name、type、score原始分数、full满分、scope、source、verified、note、原班级快照 |
| feedback | 学生+类型+日期主键；daily/weekly、startDate、text、taskIds、published、version、publishedBy/At、readBy |
| goals | 学生+当周周一散列主键；date、endDate、goal、by；同周保存更新一个当前目标 |
| progress | studentId、date、text、beforeId与afterId关联两条该学生复查记录 |
| handoffs | studentId、date、issue、reason、next、ownerId、dueDate、closed、result |
| communications | studentId、date、from、text、ownerId（主责）、closed、result |
| emotions | studentId、date、internal内部观察与支持、parentText家长说明参考；不自动发布 |
| files | 不透明业务id、studentId、subject、私有storageId、by；不向客户端返回storageId |
| audit | actor、action、target、at；学生档案/角色/个人任务关键修改额外保存change前后字段；共同作业另有history |
| requests | 用户+请求编号散列主键、action、payload散列、result；用于原子重试去重，不向客户端开放查询 |
| meta | 表名为主键、revision；云适配器查询/写入的事务修订锁，非业务记录 |

索引清单为 `indexes.json`。固定字段以关联ID表达，只有管理员能维护规范选项；不是把学校、年级、班级当自由文本标签。学生升年级/转班只修改当前档案，任务和考试快照不回写。

## 接口约定

所有入口都在 `api` 云函数，event 形式：

```json
{"action":"student","input":{"studentId":"服务器产生的学生ID"}}
```

写操作额外包含 `requestId`。客户端统一接口会在失败后原地重试时复用相同编号；服务器同时比较参数散列，重复编号用于不同内容会拒绝。参数与结果规则可直接查阅 `cloudfunctions/api/lib/domain.js`。

| 接口 | 目的 |
|---|---|
| session / register | 获取当前用户、设置称呼；不能设置自己的角色 |
| dashboard / student | 按筛选查看工作台、已授权学生详细信息 |
| adminSave | 管理学校/班级/分组/学生/已登录员工；服务器限制可写表和字段 |
| inviteCreate / inviteClaim / bindingVerify / bindingRevoke | 一次性有限邀请、申请、机构核验、撤销 |
| publishHomework / reviseHomework | 分发共同作业、确认影响后修订共同内容 |
| taskUpdate / attendanceSave | 学科进度和个人例外；到离店记录 |
| mistakeSave / reviewSave | 典型问题与独立后续复查 |
| scoreSave | 新增原始考试记录，不填充缺失成绩 |
| goalSave / progressSave / handoffSave / handoffClose | 周目标、有证据的具体变化、交接与处理 |
| emotionSave | 记录事实与支持，内外字段分开 |
| feedbackDraft / feedbackPublish / feedbackRead | 汇总草稿、主责确认发布、已阅 |
| communicationCreate / communicationClose / contacts | 家长沟通、主责处理、紧急联系入口 |
| fileUpload / fileRead / export | 上传、逐次鉴权读取字节、按当前权限导出一个学生 |

成功：`{ok:true,data:...}`。失败：`{ok:false,error:{code,message}}`。不可仅检查网络HTTP200就认定保存成功。未知服务异常向用户显示通用失败消息；业务校验会显示明确原因。所有写入及请求去重、审计一起提交。

## 作业状态与一致性

- 独立状态：待核实、未开始、进行中、待检查、检查通过、订正中、订正已复核、有遗留事项。
- “需要帮助”是独立布尔值。“免做”等是个人例外，不自动变成完成或掌握。
- 从未开始/进行中写完只能进入待检查；待检查之后老师可明确检查通过或进入订正中。
- 从订正中到已复核须操作者显式 `confirm=true`；不提供一整班自动检查通过的接口。
- 每人每份作业单独文档，三科更新不会整表覆盖。`taskUpdate` 用 version 拒绝同一任务的过期覆盖；共同内容修订用 revision。
- 同班、同日、同科、同内容与来源的重复发布复用共同记录及确定的个人任务ID，保留已有进度；同一请求并发重试只写一次。不同内容可作为新的任务发布。
- 发布最多60人，每个学生的班级、在读状态和学科权限全部通过后才事务提交，混班错误整批回滚。
- 日报是实时记录的发布时点快照，发布后不会随任务改动悄悄变化；最新进度仍单独显示。草稿、已发布和已阅分开。
- 当日验证、原题订正和后续复查分开，不自动转换成“长期掌握”。到期列表采用 `!closed && reviewDate <= 选择日期`，跨日不删除。

云适配器在事务内只调用单文档get/set。列表查询在事务外按条件分页读取，同时在事务内锁定表的meta修订；所有业务修改均更新相同修订文档，发生并发则SDK重试。写操作缓冲到完成所有读取后提交。此设计避免在事务内依赖批量where查询，但表修订锁会限制高并发吞吐；大机构须实测后升级更细粒度锁和分页接口。不要在运行期间从控制台直接改业务文档绕过修订锁。

首版按日期查询任务、按学生查询历史，每次匹配结果上限10000条，超限显式失败。未做长期大数据、云延时与费用压测。

## 文件边界

JPEG/PNG单张≤500KB。小程序选图经微信权限；云函数再次检查学生/学科权限、大小和格式头，上传到私有路径，保存不可猜的业务文件ID。读取只返回base64受限字节，不向用户发放可转发长期链接。图片头校验不能替代生产内容安全审核；涉及用户上传的内容安全审核配置须按平台当前要求补齐。

创建图片与后续卡片保存不是跨存储事务；中途取消可能留下私有孤立文件，管理员应定期清理未被mistakes引用的files及对象。不要删除仍在引用的图片。撤销权限阻止未来读取，不撤回已下载内容。

## 备份与恢复（管理员操作）

个人导出不是机构级灾备。第一版提供平台控制台备份路径，不实现自建自动备份调度服务。

1. 制定保存期限、备份频率与负责人员；建议每日备份数据库，定期复制私有存储对象。按实际云套餐使用官方备份/导出能力，敏感数据加密存放并限制下载权限。
2. 维护窗口暂停写入，记录云函数版本、环境变量**名称**、索引、安全规则及备份时间。导出所有业务集合，包括audit、requests、meta和文件元数据，保留 `_id`；不要把凭证值写入备份说明。
3. 备份私有云存储对象。仅导出files表不等于备份图片字节；记录原storageId到对象的映射。
4. 先在**独立恢复演练环境**还原，不直接覆盖正式环境。恢复所有集合、索引及拒绝客户端访问的规则，再恢复存储。
5. 跨环境导入后storageId会变化：由受信任管理员脚本或受控控制台更新files.storageId映射，不向客户端开放文件ID修改接口。重建环境内首位管理员及员工身份时注意OPENID仍绑定原AppID。
6. 暂停业务时同步校正meta修订。用至少两个家长和两名老师重跑权限、图片、并发和发布检查，比较学生数、任务数、成绩数、图片引用数，检查关键历史记录。
7. 全部通过后才安排切换；旧环境只读保留一段核对期。机构记录恢复操作的操作者、时间、备份点及验证结果。

当前未持有云资源，未实际执行云备份恢复演练。自动备份能力、保留期和恢复点目标需结合你的云套餐确认。
