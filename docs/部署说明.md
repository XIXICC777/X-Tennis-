# 零基础配置与部署

先按根目录 README 体验本地演示，再做本页。你无需先懂数据库，但必须拥有对应微信账号和机构主体权限。界面名称可能随微信开发者工具版本变化，请以控制台当前提示为准。

## 1. 准备真实小程序

1. 在微信公众平台注册小程序，记下小程序 AppID（不是公众号 AppID）。按实际教育服务功能核实服务类目、主体资质和备案，未核实前不提交正式审核。
2. 安装稳定版微信开发者工具，用管理员微信扫码登录，导入本仓库根目录。
3. 将根目录 `project.config.json` 中 `appid` 从 `touristappid` 改为真实 AppID。AppID 不是密钥，可以存在项目配置；AppSecret、云访问密钥和上传私钥都不能提交到仓库。
4. 在终端运行 `npm ci`、`npm run build`。当前项目不使用开发者工具的 TS 插件，导入的是预先编译的 JS，避免两套编译器冲突。

## 2. 创建两个独立云环境

1. 打开开发者工具“云开发”，开通服务；确认计费、配额和到期策略。
2. 创建独立的**演示环境**和**正式环境**，记录各自环境 ID。不要只靠页面上的身份切换隔离正式数据。
3. 演示环境的 `api` 云函数设置 `DEMO_MODE=true`；正式环境**不设置**此变量或设置为 `false`。修改后须重新部署并确认生效。
4. 正式环境的首次初始化另需 `BOOTSTRAP_OPENID`：首位机构管理员在此 AppID 下的微信 OPENID。它是身份标识，不是密码；不要发到公开聊天或写进仓库。可在开发者工具用微信云开发默认登录示例获取，或在部署本项目后在受控云控制台查看微信上下文。不要把页面的“账号编号”（SHA256 派生值）当成 OPENID。
5. `BOOTSTRAP_OPENID` 只用于初始化正式管理员；初始化完成后删除此配置并重新部署。新员工以后通过已登录账号编号由管理员授权。

## 3. 部署云函数

1. 在开发者工具云环境选择器中选定目标环境。
2. 右击 `cloudfunctions/api` → “上传并部署：云端安装依赖”。云函数依赖锁文件在该目录中。
3. 云函数选择 Node.js 18 或以上可用运行时（使用了 `structuredClone`）、256 MB 或以上内存、60 秒超时。若账号只提供较旧运行时，应先升级受支持运行时，不要直接运行这版代码。
4. 不创建公共 HTTP 触发器，不把初始化接口暴露为免登录 URL。业务身份只来自 `cloud.getWXContext().OPENID`。
5. 在云函数控制台“测试”中执行：

   ```json
   {"action":"initialize"}
   ```

   这是**云控制台操作**，不能在小程序客户端执行，来自小程序的初始化请求会被拒绝。
6. 演示环境会创建带 `zimo_demo_` 前缀的集合及虚构数据；正式环境创建 `zimo_live_` 集合并仅增加首位管理员，**不会灌入演示学生或成绩**。初始化只补缺失记录，不清空现有记录；演示环境不应当作真实数据环境使用。
7. 如果初始化失败，先检查 `DEMO_MODE`、`BOOTSTRAP_OPENID`、运行时、集合创建权限及函数部署状态。用户端通用失败消息不会包含私密参数。

## 4. 关闭数据库和存储的直接访问

**这一步是上线前的硬性要求。数据库默认规则或公开存储不能替代服务端权限。**

1. 在数据库中，对目标环境所有 `zimo_live_*` 或 `zimo_demo_*` 集合（包括 `users`、`files`、`requests`、`audit`、`meta`）设置自定义权限为 `docs/database.rules.json`：

   ```json
   {"read":false,"write":false}
   ```

   即客户端所有直接读写均拒绝，仅管理员和受信任云函数访问。
2. 云存储权限也设置“仅管理端可读写”，或按控制台自定义规则编辑器设置 `docs/storage.rules.json` 中拒绝客户端读写的等效规则。不同云存储产品控制台可能要求布尔表达式形式，请确认发布后的效果，而非仅复制文字。
3. 确认没有公共 CDN、静态网站或“所有用户可读”的存储桶权限。业务代码不返回 fileID、公开链接或临时下载 URL；`fileRead` 每次校验绑定并通过云函数返回受限图片字节。
4. 权限实测：普通家长在开发者工具控制台直接 `wx.cloud.database().collection('zimo_live_students').get()` 必须失败；用已知云存储 fileID 直接 `wx.cloud.downloadFile` 必须失败。然后用小程序获授权图片查看按钮必须成功；撤销绑定后再次请求 `fileRead` 必须失败。
5. 图片和已导出的信息一旦由获授权用户保存或截图，无法远程撤回；指导员工只在必要范围内分享。

## 5. 索引

1. 按 `docs/indexes.json` 为目标前缀集合建立所列索引。数组中的字段按顺序全部升序；`_id` 自带唯一索引。
2. 先建 `tasks.date + _id`、各业务表 `studentId + _id` 以及 `bindings.userId + verified + active + _id`，再补齐其余查询索引。
3. 不要把“字段已存在”当成“索引创建完成”。等待控制台完成索引构建；如实际云查询返回索引要求，按提示建立相同字段次序并重试。
4. 首版按日期加载全机构任务，按学生加载个人历史；扫描上限为**单次匹配查询10000条**，超限明确报错，不静默截断。大型机构上线前应做云端容量、超时和并发验收。

## 6. 让小程序连接云环境

编辑 `miniprogram/config.ts`：

```ts
export const config: {mode:'local-demo'|'cloud';envId:string} = {
  mode: 'cloud',
  envId: '填写目标云环境ID'
};
```

运行 `npm run build` 并重新编译小程序。云演示模式会由服务端返回黄色演示标志；正式环境不会显示演示身份入口，传入 `demoPersona` 也不能改变身份。

正式模式无须启动本地演示服务。所有业务、图片和导出请求均调用 `api` 云函数。不要把本地 HTTP 地址登记为正式合法域名，也不要在正式版关闭域名校验。

## 7. 首次建档

1. 首位管理员进入“机构管理”，添加学校、学年与学校班级、机构分组。
2. 每位老师先扫码进入小程序；系统在服务端以微信身份创建普通家长账号。老师点击“修改称呼”，复制页面显示的“账号编号”给机构管理员。
3. 管理员点“授权已登录员工”，输入编号、姓名和角色代码。普通老师填写 `teacher`；兼主责职责可填 `teacher,lead`；管理人员可填 `admin,teacher,lead`。客户端只能提交申请，服务端仍检查当前操作者是否管理员。
4. 老师刷新后获得职责。管理员给每位学生设置唯一编号、当前学校班级、机构分组、主责老师和三科分工。
5. 主责老师生成邀请，家长申请后，老师按原登记联系方式或线下当面核验，核验通过才能看到孩子。

## 8. 真实环境验收后再提交审核

至少使用两部手机、两个家长账号和两名老师完成 `验收报告.md` 中的真实云联调清单。重点确认数据库与存储直接访问拒绝、并发事务冲突重试、图片预览、导出文件分享和身份隔离。当前开发机没有 AppID、微信登录和云资源，因此这些检查尚未执行。

## 9. 常见问题

- **本地演示无法连接**：终端先运行 `npm run demo`，保持运行，确认端口8787未被占用；模拟器允许本地请求。真机改用云演示环境。
- **config.js模块未定义**：在开发者工具导入的同一个目录运行 `npm run build`，确认输出“模块检查通过”；再在开发者工具清除全部缓存并重新编译。新版下载包附带完整JS，启动演示也会自动构建检查。请勿启用第二套TS编译插件。
- **修改代码没变化**：执行 `npm run build` 后再点编译；不要编辑生成的 JS。
- **无权限**：核对当前微信身份、员工是否启用、三科分工、主责老师、监护绑定的核验和有效状态；不要直接放宽数据库规则。
- **保存失败**：表单保留，检查错误后原地重试；不要刷新页面后重复新建。原地重试携带原请求编号，同内容同班同日作业也有服务端去重。
- **事务冲突**：云适配器使用 SDK 冲突重试。仍失败时刷新版本再保存，不能覆盖其他老师结果。
- **图片太大**：首版仅接受JPEG/PNG且单张≤500KB，先压缩。上传已成功但后续表单取消会留下未关联私有文件，定期由管理员清理。
- **平台隐私提示**：在小程序后台完成隐私指引和所需接口声明，再按当前基础库要求授权；取消选择媒体不会冒充保存成功。
