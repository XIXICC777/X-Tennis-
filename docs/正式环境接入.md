# 正式环境接入操作单

正式环境ID：`zimo-prod-d6gt9vooh5852c299`。原演示环境 `cx100-d3ga3i1ljcfc054ca` 保留独立使用。当前客户端TS及编译JS已指向正式环境；该配置更新不代表云函数、数据库已部署或微信已审核发布。

## 1. 下载并导入新项目

将正式配置包解压到新文件夹，保留原演示项目和其中的本地配置。用你注册的真实AppID导入包含project.config.json的根目录。仓库的touristappid是占位值，不是你的注册AppID。下载包已附完整JS；修改TS后才需要重新运行npm ci、npm run build。

## 2. 上传到正式环境

打开云开发控制台并选中 `zimo-prod-d6gt9vooh5852c299`。右键本项目cloudfunctions/api，关联这个正式环境后“上传并部署：云端安装依赖”。支持Node16.13及以上，设置超时60秒、内存256MB或以上。

正式环境的DEMO_MODE必须不设置或设置为false。不要复制演示环境的DEMO_MODE=true，不要复制zimo_demo_*集合、文件或虚构账号。此时数据库尚未初始化，页面加载业务记录可能提示配置失败，先继续配置首位管理员。

## 3. 获取首位管理员本人微信身份

保持使用管理员本人登录的真实小程序AppID，在开发者工具编译新项目，打开“调试器 → Console”，执行：

```js
wx.cloud.callFunction({
  name: 'api',
  config: {env: 'zimo-prod-d6gt9vooh5852c299'},
  data: {action: 'identity'}
}).then(function(r) { console.log(r.result); });
```

返回ok:true及data.openid。这个接口只返回已登录调用者自己的微信OPENID，忽略客户端指定的身份，不读取数据库，也不会修改角色。云控制台测试没有个人OPENID，不能替代这个步骤。

将本人OPENID直接复制到正式api的云函数环境变量BOOTSTRAP_OPENID。不要把页面“我的账号编号”（SHA256派生ID）当作微信OPENID，不必把OPENID发到聊天里或提交到仓库。若调用失败，先确认api已上传到这个环境、AppID与环境关联正确。

## 4. 初始化正式数据库及首位管理员

确认DEMO_MODE为false或未设置，BOOTSTRAP_OPENID为本人微信身份；保存并使配置生效。在正式api的**云端测试**中执行：

```json
{"action":"initialize"}
```

成功会创建zimo_live_*集合、meta修订记录和你指定的首位管理员，不添加虚构学校、学生、成绩或作业。首位管理员即使已提前登录成为默认家长，可信控制台初始化也会赋予管理员职责，保留姓名且不会重复创建账号。客户端不能自行调用初始化。

成功后删除BOOTSTRAP_OPENID环境变量并使配置生效，再编译刷新小程序验证管理员工作台。以后新增员工由管理员按账号编号授权，不再通过首位管理员配置反复切换负责人。

## 5. 权限、索引及正式档案

- 对全部zimo_live_*集合（含users、files、requests、audit和meta）设置客户端read:false/write:false。
- 正式云存储设置仅管理端读写，拒绝直接公开下载；图片通过fileRead接口逐次鉴权读取。
- 按docs/indexes.json在zimo_live_前缀集合建立索引，确认构建完成。
- 由管理员依次维护学校、学年班级、机构分组、员工授权、学生及三科分工，再生成邀请并线下核验监护人。
- 正式家长与员工都用各自真实微信登录。角色来自服务器，页面不会显示虚构演示身份选择。

## 6. 上线前验证

用户已反馈原独立演示环境手机读写正常；这不证明正式环境已通过验收。正式环境还需两名真实员工及两个监护账号验证授权、分工、发布、图片、导出、撤销绑定与越权拒绝，完成备份恢复及索引检查。

在开始录入真实儿童信息前，完成相应告知、监护人必要授权及隐私配置。微信后台的实际服务类目、所需主体资质、备案和审核须单独完成；注册成功、云环境创建、手机预览均不等于正式审核通过。
